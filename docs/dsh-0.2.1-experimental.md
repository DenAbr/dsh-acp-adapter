# DSH 0.2.1 实验功能与 ACP 的集成审计

本轮目标是复用官方能力和原生 UI，使已经使用 ACP 的用户无需增加模型路由、配置文件或操作步骤。这里记录采用方向、必要的适配边界与验收范围；不代表已经合并到 main 或发布。验证结果由实际执行记录填写，源码分析与待执行用例不能记为通过。

兼容目标是 `package.json` 中精确锁定的 DSH `0.2.1-alpha.2`；源码依据固定为 [`d743267388641bc76f17c45ce8b4c231aed1d32c`](https://github.com/deepseek-ai/deepseek-harness/tree/d743267388641bc76f17c45ce8b4c231aed1d32c)。正常用户仍通过原生 Plugins 页选择官方组合包。本插件不增加第二套开关、模型选择器、翻译 renderer、语音 composer 或 Ralph 调度器。未开启的可选组合包继续由官方配置层管理。

## 条件加载的准确边界

结论是：**官方可选服务按启用状态激活，适配器的通用兼容代码随插件载入；不能声称每个适配模块都按实验开关懒加载。**

1. 安装不等于启用。官方 profile 只组合已选 bundle；原生开关添加/移除其 patch layer，保留安装依赖。Loader 在 disabled 判定后才进入 import/mount，Cordis 在所需服务齐备后才激活。客户端仅发现有效 fiber 的模块，并随 manifest 删除旧 fiber。未启用的翻译器、语音模型、PTY registry、搜索索引、Ralph workflow 或 Inspector Worker 不由适配器创建。
2. 导入不等于运行。审查起点 `94977fd` 的 127 个 TypeScript 文件中，实验包引用为五个 Teams 类型导入、零个运行时导入；Hooks/Webhook 的非 experimental 前缀名称另行核对。生产 dependencies 和 `cordis.patch.yml` 不安装或开启这些能力。该版构建产物也没有实验包运行时导入；开发依赖与 E2E 安装锚点不属于产品入口。
3. 通用 ACP MCP 桥、图片判定、目录保护和会话观察随适配器载入。工具桥只消费当前准入 schema 与实际 scoped registry 的交集；工具或 owner 撤销后旧 lease 失效。目录保护还负责核心 `working_directory`，即使 Worktree 实验关闭也必须保留。不能为追求表面上的“全懒加载”关闭这些安全边界。
4. 客户端当前是单个 bundle，Teams 组件代码/CSS 也在其中。关闭功能不会卸掉已经导入的字节；是否显示入口、订阅业务状态及执行操作要单独核对。缓存投影不证明插件仍启用，本轮发现的 Teams 热关闭残留按官方 UI contribution 生命周期修复，见下方新增验收记录。
5. 无 HMR 的部署可能返回 `restart-required`，不能承诺开关立即清理运行资源。`dump-config-schema` 可导入已组成但被 disabled 的 row 读取 schema，仍不 mount；未选 bundle 不产生这些 row。Node/browser 模块缓存也不会因关闭而释放全部代码。

源码依据：[profile 组合](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/boot/app-boot/src/profile.ts#L739)、[原生开关](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/boot/plugin-manager/src/index.ts#L476)、[Loader](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/vendor/loader/src/config/entry.ts#L111)、[客户端模块](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/client/modules/src/index.ts#L981)、[schema 诊断例外](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/boot/app-boot/src/config-schema/collect.ts#L201)。这是完整入口的源码覆盖，运行证据按上表区分；已有 Schedule 实际启停和通用 lease 撤销用例不能替代全部 11 组合包的 on/off 验收。

## 第一阶段：思考翻译、语音输入、搜索与持久终端

CoT 的官方链路为 `cot-translation-bundle` → `translator` 与 `client-ui-cot-translation` → [`conversation.chat.reasoning.body`](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/experimental/client-ui-cot-translation/src/client/mount.ts#L101) → `TranslationBody` → 原生 `conversation.chat.reasoning.content`。官方翻译贡献的默认 priority 为 0，原生 fallback 为 100；ACP 保留原生 renderer 注册树及优先级，使翻译自然作用于归一化后的思考文本。适配器不把译文写回模型思考或助手消息。

[`ReasoningTranslation`](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/experimental/client-ui-cot-translation/src/client/translation.ts#L57) 按完整段落翻译，stream 进行中保留未完成尾段；stream 结束后才翻译尾段。官方控件负责原文切换、翻译状态、失败、重试与折叠时的请求取消；官方 translator 负责可复用的持久译文。采用这些已有行为，无新增用户配置。验收使用 loopback HTTP endpoint 模拟 Bing 协议，不向真实 Bing、Google 或付费模型发请求；这证明 Host/Remote/renderer 链路，不能证明外部服务质量或可用性。

Voice 的官方链路为 `voice-input-bundle` → `speech-to-text` provider registry → `api-speech-to-text` → [`conversation.input.activity`](https://github.com/deepseek-ai/deepseek-harness/blob/d743267388641bc76f17c45ce8b4c231aed1d32c/packages/experimental/client-ui-voice-input/src/client/mount.ts#L45) → `VoiceInput` → 原生 `inputActions.insertText`。语音结果先进入当前草稿，由用户审阅并发送，ACP 最终只收到原生 composer 准入后的 prompt。录音、转写取消和插入位置冲突由官方生命周期处理。

采用 Voice 时沿用原生普通 composer。ACP 固定选项权限问答继续使用已有问答 composer；该界面没有普通文本草稿，不额外塞入录音入口。验收关闭 SenseVoice，注册本地模拟识别器，并以 Chromium 虚拟音频设备测试真实录音、WAV 编码和 Remote 转写链路；不下载模型或占用物理麦克风。Electron helper 当前未转发虚拟媒体参数，因此该 Voice 用例明确跳过 Electron。真实麦克风权限、SenseVoice 安装/推理和完整桌面产品仍需各自验收。

| 领域     | 官方生产与消费链路                                                                                                                                                                                                                                                                    | 本轮采用判断与必须保留的边界                                                                                                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 会话搜索 | `experimental/session-search/cordis.patch.yml` 建立隔离的 `sessionQuery`；`session-query/session-query-sqlite` 提供索引；`experimental/tool-session-query/src/index.ts` 注册 `session_search`、`session_event_search`、`session_trace`、`session_event_trace`、`session_event_read`。 | 沿用官方工具和 workspace 授权范围，经已有 ACP MCP 工具桥执行。复用历史查询、当前 step 排除及原生工具结果，不维护第二套搜索索引。明确指定其他 workspace 的 session ID 仍须拒绝；本机 keyless Host 用例已通过。         |
| 持久终端 | `experimental/terminal-bundle/cordis.patch.yml` 建立隔离 registry 和平台 shell backend；`experimental/tool-terminal/src/index.ts` 注册六项 `terminal_*` 工具；`terminal/terminal` 管理 owner 和 PTY 生命周期。                                                                        | 沿用官方 PTY、owner、权限和取消机制，经 ACP MCP 调用。持续 shell 状态归原生 registry，用户交互终端继续使用原生入口。取消单次等待和销毁 PTY 是不同操作；跨会话读写、信号和关闭必须拒绝；本机 keyless Host 用例已通过。 |

Worktree 的准入保护见 [working-directory-guard](../src/host/composition/working-directory-guard.ts)。保护由原生 tools guard 执行，覆盖普通工具与 PTC inner call，在 Git 或 cwd 副作用发生前判断。切换在当前 prompt 终态和 Host 反馈排空后执行，通过 `session/fork` 保留远端上下文，不清空绑定或自动重放历史。已确认 Agent 支持保留上下文的 fork 时，Stop 若发生在 fork RPC 派发前，已知的 `cwd-handoff-pending` 在下次继续时自动完成交接，原生待继续 UI 不要求额外恢复点击；RPC 已派发但结果不明时仍保留 outcome-unknown 恢复门禁，不自动重新派发。身份、目录或 launch 指纹不能证明匹配时也保留真实恢复界面。不支持 fork 的 Agent 若被工具桥以外的入口修改 cwd，并同时 Stop，仍保留 `reconciliation-required/cwd-changed`，不能写成可自动继续的 pending；本轮最后复核修复了该组合边界并补充单测。

图像适配的所有者见 [模型能力适配](../src/host/composition/profile-adapter.ts)、[连接能力有效期](../src/runtime/session/session-runtime.ts) 与 [原生工具桥](../src/host/teams/bridge.ts)。它使已有官方 MCP 图片投影能够正确判断调用会话；不等于已经验收实际浏览器、computer-use provider、桌面截图或供应商视觉模型。
